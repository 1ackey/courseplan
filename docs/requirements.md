# 英语学院课程信息平台 — 需求文档 v3.0

> 参考项目：[csdiy.wiki](https://csdiy.wiki/)

---

## 1. 项目概述

### 1.1 背景与问题

对外经济贸易大学英语学院选课系统仅列出课程名称和编号，不展示课程的核心信息。每门课开课后，教师会发放一份 **教学进度表**（Word 文档），其中包含课程基本信息 + 按周排布的教学计划，但这份文档仅在选课后才能看到。

学生选课时对「这门课学什么、怎么教、怎么考」缺乏了解渠道，只能依赖学长学姐口口相传，信息零散、不可检索。

### 1.2 目标

构建一个结构化、可搜索、可持续更新的课程信息平台，**以教学进度表为核心数据源**，让院内学生选课前能基于课程内容本身做出判断。

### 1.3 定位与边界

| 是 | 否 |
|----|-----|
| 展示教学进度表（按周内容 + 教学方式） | 不提供主观评分 / 难度评级 |
| 展示考核方式（考试/论文/占比） | 不记录给分情况 / 挂科率 |
| 按课程类别和教师两种维度组织浏览 | 不记录点名频率 / 作业量 |
| 全文搜索 | 不做推荐 / 排序 / 对比 |

> 核心理念：选课应基于内容。本平台是信息的搬运工，不是观点的放大器。

## 2. 参考项目分析：csdiy.wiki

### 2.1 csdiy.wiki 的设计特点

| 层面 | 做法 |
|------|------|
| 站点生成 | Material for MkDocs |
| 导航 | 左侧多级目录树（大类 → 小类 → 单页），导航配置在 `mkdocs.yml` 中声明 |
| 单页设计 | 每门课程一个独立 Markdown 页面，包含课程简介、资源链接、学习建议等 |
| 首页 | 前言式长篇介绍，引导用户了解项目背景和使用方式 |
| 搜索 | MkDocs Material 内置搜索，覆盖全站内容 |
| 贡献 | GitHub PR，提供邮件和 issue 入口 |
| 部署 | GitHub Pages，通过 GitHub Actions 自动构建 |
| 评论 | Material for MkDocs 内置评论插件（可选） |

### 2.2 参考与差异

| 方面 | csdiy.wiki | 本项目 |
|------|-----------|--------|
| 定位 | 全球 CS 自学课程汇总 | 单一学院课程信息系统 |
| 内容深度 | 每课简短介绍 + 资源链接 | 完整教学进度表（表格密集） |
| 导航层级 | 3-4 层 | 2-3 层（类别 → 课程） |
| 首页 | 长文介绍 | 搜索入口 + 类别卡片 + 教师索引入口 |
| 部署 | GitHub Pages | 自有服务器 Nginx |

## 3. 前端设计

### 3.1 首页布局

```
┌──────────────────────────────────────────┐
│                                          │
│      🔍  课程名称 / 代码 / 教师 / 关键词     │
│                                          │
│      ──    快速导航    ──                  │
│   基础必修 · 基础选修 · 专业方向课 · 实验课     │
│   按教师浏览 · 贡献指南 · 关于本站             │
│                                          │
└──────────────────────────────────────────┘
```

- **搜索框为主**，占据页面核心视觉焦点（类似 csdiy.wiki 首页风格）
- 搜索支持：课程名称、课程代码、教师名、内容提要关键词
- 搜索框下方提供文字式快捷导航入口
- 不在首页展示课程列表/卡片，引导用户搜索

### 3.2 课程类别页

```
左侧导航树              主内容区
┌──────────┐    ┌────────────────────┐
│ 基础必修   │    │ # 基础必修           │
│ 基础选修   │    │                    │
│ 专业方向课◀│    │ 共 12 门课程        │
│   ENG820  │    │                    │
│   语用学   │    │ - [ENG820 语用学]   │
│   ENGxxx   │    │   向明友 · 专业方向课│
│ 实验课    │    │                    │
│           │    │ - [ENGxxx XXX]     │
│           │    │   教师名 · 类别     │
└──────────┘    └────────────────────┘
```

- 左侧导航树由 `mkdocs.yml` 配置，层级展开
- 主内容区列出该类别下所有课程，一行一卡，显示：课程名称、代码、教师、学分/课时
- 每行可点击进入课程详情页

### 3.3 教师索引页

```
# 按授课教师浏览

## 向明友
- [ENG820 语用学](../categories/major-direction/ENG820/) · 专业方向课

## 张三
- [ENGxxx YYY](../categories/basic-required/ENGxxx/) · 基础必修
```

- 按教师名分组，名下列出所授课程，点击跳转至课程详情页
- **自动生成**：由脚本扫描所有课程 Markdown 文件，提取教师字段，自动生成教师索引页 `teachers/index.md`
- CI 构建时自动执行，确保教师索引与课程文件始终同步

### 3.4 课程详情页（核心页面）

```
┌─────────────────────────────────────────────┐
│ # 语用学                                     │
│                                             │
│ | 字段 | 内容 |                              │
│ |------|------|                              │
│ | 课程代码 | ENG820 |                         │
│ | 课程类别 | 专业方向课 |                      │
│ | 任课教师 | 向明友 |                          │
│ | 开课学院 | 英语学院 · 语言学系 |              │
│ | 总课时 / 周课时 | 32 / 2 |                  │
│ | 教学周数 | 16 |                            │
│ | 考核方式 | 平时40% + 期末闭卷60% |           │
│                                             │
│ ## 教学进度                                   │
│                                             │
│ | 日期 | 周次 | 课时 | 教学方式 | 内容提要 | 备注 |   │
│ |------|------|------|----------|----------|------|   │
│ | 3.11 | 1 | 2 | 研讨 | General Intro(1) | 教师主讲 |   │
│ | 3.18 | 2 | 2 | 研讨 | Defining Pragmatics(2) | 教师主讲 | │
│ | ...  | ...| ...| ... | ... | ... |              │
│                                             │
│ 最后更新：2026-03-09 · [反馈问题](github issue)    │
└─────────────────────────────────────────────┘
```

- **上部**：课程元信息表（2 列 key-value）
- **下部**：教学进度表（按周排布，完整还原教学进度表）
- **移动端适配**：大屏使用 Markdown 表格完整展示；小屏（< 768px）每行转为卡片式布局，避免横向滚动
- **底部**：最后更新时间 + 反馈链接
- 页面使用 Material for MkDocs 的 `admonition` / `table` 等原生特性

### 3.5 导航配置（mkdocs.yml 关键结构）

```yaml
nav:
  - 首页: index.md
  - 按课程类别:
    - 基础必修:
      - categories/basic-required/index.md
    - 基础选修:
      - categories/basic-elective/index.md
    - 专业方向课:
      - categories/major-direction/index.md
    - 实验课:
      - categories/lab/index.md
  - 按授课教师:

  - 关于本站: about.md
```

- 利用 Material for MkDocs 的 `navigation.indexes` 特性，section 页面可作为索引页

## 4. PR 贡献工作流（「后端 PR 接口」）

### 4.1 整体流程

```
贡献者 fork 仓库
    │
    ├─ 复制 templates/course-template.md
    ├─ 填入课程信息（元信息 + 教学进度表）
    ├─ 放在正确的类别目录下
    └─ 提交 PR
       │
       ▼
PR 自动触发 CI 检查
    ├─ ✅ 格式校验通过 → 通知维护者 review
    └─ ❌ 格式校验失败 → PR 评论提示修复点
       │
       ▼
维护者 Review
    ├─ 内容完整性检查（是否所有必填字段已填）
    ├─ 信息准确性抽查
    ├─ 合并 PR
    │
    ▼
GitHub Actions 自动构建 + 部署到服务器
```

### 4.2 PR 模板（`.github/PULL_REQUEST_TEMPLATE.md`）

```markdown
## 课程信息

- 课程名称：
- 课程代码：
- 课程类别：基础必修 / 基础选修 / 专业方向课 / 实验课
- 任课教师：
- 信息学年：20xx-20xx 学年第x学期

## 数据来源

- [ ] 来源于教师发放的教学进度表
- [ ] 考核方式已单独确认

## Checklist

- [ ] 已使用课程模板填写
- [ ] 文件放置在正确的类别目录下
- [ ] 所有必填字段已填写
- [ ] 教学进度表已完整录入
- [ ] Markdown 格式正确（本地 `mkdocs serve` 预览通过）
```

### 4.3 CI 自动校验（GitHub Actions）

在 PR 提交时自动执行：

| 检查项 | 工具 | 说明 |
|--------|------|------|
| Markdown 语法 | `markdownlint` | 基础格式校验 |
| 必填字段完整性 | 自定义脚本 | 检测模板中所有必填字段是否已填写 |
| 教学进度表格式 | 自定义脚本 | 确认进度表有表头且至少一行数据 |
| 文件路径正确 | 自定义脚本 | 确认文件放在正确类别目录 |
| 站点构建测试 | `mkdocs build --strict` | 确保新增内容不会导致构建失败 |

校验失败时，自动在 PR 下评论具体错误，引导贡献者修复。

### 4.4 自动部署（GitHub Actions → 服务器）

```yaml
name: Deploy
on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.x'
      - run: pip install mkdocs-material
      - run: mkdocs build --strict
      - name: Deploy to Server
        uses: easingthemes/ssh-deploy@v4
        with:
          SSH_PRIVATE_KEY: ${{ secrets.SERVER_SSH_KEY }}
          REMOTE_HOST: ${{ secrets.SERVER_HOST }}
          REMOTE_USER: ${{ secrets.SERVER_USER }}
          TARGET: /var/www/courseplan/
          SOURCE: site/
```

部署方式：
1. GitHub Actions 构建 `mkdocs build`
2. 通过 rsync/SCP 将 `site/` 目录推送到服务器的 Nginx 目录
3. 服务器上 Nginx 直接托管静态文件

### 4.6 仓库保护设置

- `main` 分支开启 branch protection
- 禁止直接 push 到 `main`
- PR 必须通过 CI 检查才能合并
- 至少一位维护者 approve 才能合并

## 7. 设计决策记录

| # | 决策点 | 结论 |
|----|--------|------|
| 1 | 首页风格 | 搜索框为主（类似 csdiy.wiki） |
| 2 | 教师索引 | 脚本自动生成，CI 构建时执行 |
| 3 | 进度表移动端 | 卡片式布局替代横向滚动表格 |
| 4 | 辅助脚本 | 不需要，贡献者手写 Markdown |
| 5 | 部署 | 已有服务器，GitHub Actions → rsync → Nginx |
| 6 | 首页卡片 | 不展示课程卡片，搜索为唯一入口 |
